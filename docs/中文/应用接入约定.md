# 让自己的应用出现在设备上：HubDeck contract

原文：[docs/APP-CONTRACT.md](../APP-CONTRACT.md)。基线 `0cbdde3`，2026-10-22。

任意应用、脚本或用 Claude Code 构建的工具，都可在不了解 HubDeck 内部的前提下显示状态并提供按键动作。应用负责发布，HubDeck 订阅，其他程序也可监听。

全部能力均可选。只实现 `GET /hubdeck/status` 已可工作。

## 1. 状态：`GET /hubdeck/status`

使用应用自身的本机端口，地址 `http://127.0.0.1:<port>/hubdeck/status`，返回 JSON：

```json
{
  "app": "Agent Desk",
  "items": [
    { "id": "1", "label": "Agent 1", "state": "waiting", "text": "Needs your OK" },
    { "id": "2", "label": "Agent 2", "state": "working", "text": "Writing tests", "value": 0.4 }
  ]
}
```

- `id`：每个 session、job、build 等条目的稳定标识。HubDeck 形成 `<source>.<id>`，如 `launcher.1`；一键显示一个条目，dial 可统计 `launcher.*`。
- `state`：使用下表状态；其他值按中性颜色的文本显示。
- 可选 `label` 为条目名，`text` 为当前情况的一行简述，`value` 为数字（0..1 进度或计数）。

| state | 含义 | 按键显示 |
|---|---|---|
| `waiting` | 需要用户 | 橙色、手；设备边缘橙色脉动 |
| `working` | 正忙，无需操作 | 蓝色、旋转箭头 |
| `done` | 已结束，值得查看 | 绿色、勾 |
| `error` | 失败 | 红色、叉 |
| `idle` | 无事进行 | 灰点 |
| `offline` | 没运行或无法访问 | 暗色、短横 |

没有 event stream 时，按键或 dial 显示应用期间 HubDeck 才读取，最快每 5 s 一次。

## 2. 实时变化：`GET /hubdeck/events`

Server-Sent Events stream，`Content-Type: text/event-stream`；每条 event 携带变化条目，结构相同：

```
data: {"items":[{"id":"1","state":"working","text":"Back to work"}]}

```

连接应用期间订阅；stream 断开会重连，每次连接或重连后读取一次 `/hubdeck/status`。其他程序也可订阅。

## 3. 按键动作：`GET /hubdeck/manifest`

应用描述自身，HubDeck 和助手据此构建按键：

```json
{
  "app": "Agent Desk",
  "exe": "agent-desk.exe",
  "status": "http://127.0.0.1:4317/hubdeck/status",
  "events": "http://127.0.0.1:4317/hubdeck/events",
  "actions": [
    { "id": "focus", "label": "Focus agent", "icon": "bot", "method": "POST", "url": "http://127.0.0.1:4317/agents/{id}/focus" },
    { "id": "new", "label": "New agent", "icon": "plus", "method": "POST", "url": "http://127.0.0.1:4317/agents" },
    { "id": "open", "label": "Open", "icon": "app-window", "link": "agent-desk://open" }
  ]
}
```

- 动作可以是 HTTP call（`method`、`url`、可选 `body`），或 `link`（应用注册的 deep link，像普通地址打开）。显示条目时，URL 的 `{id}` 替换为条目 id。
- 可选 `icon` 为 HubDeck 图标名，见 `list_icons`。
- manifest 也可作为应用旁的 `hubdeck.json` 文件，由用户选取。

## 4. 没有 server：直接 push

不能提供 HTTP 的脚本可直接调用 HubDeck 本地 API；端口在 `%APPDATA%\dev.hubdeck.app\api-http-port`，token 在 `api-token`：

```
curl -X POST http://127.0.0.1:<port>/api/state -H "Authorization: Bearer <token>" \
  -d '{"source":"backup","items":[{"id":"nightly","state":"done","text":"12 GB"}]}'
```

## 5. 在 HubDeck 连接应用

**自动连接，推荐**：应用启动时 announce manifest，HubDeck 无需点击即可连接，并在窗口提示：

```
POST http://127.0.0.1:<port>/api/apps/announce   Authorization: Bearer <token>
{"url": "http://127.0.0.1:4317/hubdeck/manifest"}
-> {"ok": true, "id": "example-app", "new": true}
```

`<port>` 和 `<token>` 分别在 HubDeck 数据目录的 `api-http-port`、`api-token`。Windows 为 `%APPDATA%\dev.hubdeck.app\`，macOS 为 `~/Library/Application Support/dev.hubdeck.app/`。文件不存在或请求失败代表 HubDeck 没运行，安静继续即可。已有连接会刷新以接收 manifest 变化；用户曾主动断开的应用会被拒绝（`400`），直到手工重新添加。示例见 `scripts/example-app.py`。

**手动连接**：Settings > Connections > Your apps > Add 输入 manifest 或 status 地址。助手也可用 `connect_app` 连接本机地址。

> 为这个应用添加 HubDeck 集成，遵循 https://github.com/<owner>/hubdeck/blob/main/docs/APP-CONTRACT.md ：在应用现有本机端口（或仅绑定 127.0.0.1 的新端口）提供 `GET /hubdeck/status`，每个值得展示的 <session / job / 事项> 一个条目，使用共享状态：需要用户时 waiting，以及 working、done、error、idle、offline。提供 `GET /hubdeck/events`，以 Server-Sent Events 发送变化条目；提供 `GET /hubdeck/manifest`，把有用动作列为 HTTP call 或 deep link。启动时向 HubDeck announce manifest（`POST /api/apps/announce`，见第 5 节；HubDeck 没运行则安静继续）。除动作外保持只读；除绑定 127.0.0.1 外不额外认证。添加测试，确认三条 endpoint 按 contract 结构应答。
