# 架构

原文：[ARCHITECTURE.md](../../ARCHITECTURE.md)。译文基线 `0cbdde3`，2026-10-22。以下时间、目标与验证记录沿用原作者表述。

面向 Cooler Master MasterHUB 模块化控制器的开源桌面软件，支持 Windows 和 macOS。
产品名为 **HubDeck**（2026-10-09 确定；名称不得使用“MasterHUB”或“Cooler Master”，描述中可以写“for the Cooler Master MasterHUB”）。Tauri 标识为 `dev.hubdeck.app`，Rust 包名为 `hubdeck`。仓库文件夹与私有 GitHub 仓库仍叫 `masterhub`；公开仓库将以干净导出的形式发布，名称为 `hubdeck`。

## 目标

1. 替代官方应用：所有模块可用，设置持久保存，后台保持轻量。
2. 同时支持手工定制（设置窗口）和代码定制（插件），二者使用相同的插件模型。
3. 允许 agent 编写脚本：本地 API、CLI 和 MCP server 可以控制设备并读取状态。
4. 可发布：签名安装包（`.msi`、`.dmg`）、自动更新、CI 和文档。

## 目录

```text
crates/
  mh-protocol   HID 协议：模块类型、report 编解码、图片分块。没有 I/O；有单元测试。
  mh-device     hidapi 传输、热插拔 hub（枚举、初始化、重连）、事件流、退出时释放。
app/            Tauri 2 外壳（src-tauri）+ React/TypeScript UI（设置窗口、托盘）。
plugins/        随应用分发的内置插件（动作）。
prototype/      用于在硬件上发现并验证协议的 Python 原型。
PROTOCOL.md     经实机验证的协议（mh-protocol 的依据）。
```

## 运行时

```text
模块（USB HID） ──> mh-device hub ──> engine ──> profile（控件 -> 动作）
                       ^  事件           │  │
                       └── 绘图/LED ─────┘  ├─> 插件宿主（WebSocket，每插件独立进程）
                                           ├─> 本地 API（127.0.0.1 上的 HTTP + WebSocket）<── CLI、MCP、hooks
                                           └─> 设置 UI（Tauri IPC）
```

- **Hub**：每个模块一个读取线程；读取出错意味着模块从底座移除。hub 每秒重新枚举，为返回的模块重新初始化（按键和 dial 切入 software mode），并要求 engine 重绘。退出、休眠或设置变化时，把按键和 dial 交回 hardware mode。
- **Engine**：持有活动 profile，将事件路由给动作，渲染按键、整面板和 dial 图像，驱动 LED。所有 HID I/O 都在阻塞线程上运行，不占用 async runtime 或 UI 线程。
- **Profiles**：存储为应用数据目录内的 JSON，原子写入（临时文件 + rename），通过 `"version"` 字段和向前迁移管理版本。profile 可以指定布局（当前连接的模块），更换模块时便能自动切换。
- **Plugins**：独立进程，带有 `manifest.json`（动作、以 JSON Schema 描述的参数、图标）。设置 UI 根据 schema 生成各动作表单。通信协议在按键、dial 等概念一致的部分遵循 OpenAction / Stream Deck SDK，并扩展推杆、滚轮、LED 和整面板屏幕。用户私有插件放在仓库外的个人插件目录。
- **Local API**：监听 `127.0.0.1` 的 HTTP + WebSocket，使用每次安装独有的 token。CLI、MCP server 和 Claude Code hooks 等工具用它把状态推到设备上。

## 安全

模块固件接受重写序列号、保存工厂数据、复位模块和刷写固件等命令。`mh-protocol` 不为这些命令提供编码 API，raw-report 通道也会拒绝相应命令字节。固件升级不在项目范围内。

## 权利与来源
