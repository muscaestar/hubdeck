# 为 HubDeck 贡献

原文：[CONTRIBUTING.md](../../CONTRIBUTING.md)。基线 `0cbdde3`，2026-10-22。

感谢帮助。欢迎提交 issue 和 pull request。

## 报告问题

请包含：

- 系统（Windows 或 macOS 版本）和 HubDeck 版本；
- 已连接的模块及其位置（照片有帮助）；
- 操作过程、预期结果和实际结果；
- 诊断文件：Settings > Help and about > Save diagnostics（或托盘菜单）。其中包含版本、模块与日志，网页地址、密钥和路径已去除。

若按键模块或 dial 不再显示图片，且窗口提示无响应，把模块从底座取下再装回。Windows 窗口还提供“Restart module”；macOS 下 HubDeck 重试几次后自行重启模块。请说明发生过程：这是项目正在规避的固件问题，每份报告都有帮助。

## 分享插槽数据

HubDeck 根据模块使用的 USB 端口判断其位置。多数位置来自映射表，其中只有部分插槽实机核实过。如果“Arrange modules”显示错误位置或朝向，先手动调整，再提交 issue，注明模块类型、模块下方的 slot（例如 `keys · 2-3`），以及你设置的位置与旋转角度。

## 代码

- Rust：必须通过 `cargo fmt`、`cargo clippy` 和 `cargo test -p mh-protocol -p mh-device -p hubdeck`。HID I/O 只能在自己的线程运行，不进入 UI 线程或 async runtime。
- TypeScript：必须通过 `app/node_modules/.bin/tsc --noEmit -p app` 和在 `app/` 中执行的 `pnpm test`。
- 所有面向用户的文本经 `app/src/i18n.ts` 处理（英文优先，其他语言回退到英文）。
- 不得添加发送固件升级、序列号、工厂数据、恢复出厂或保存 flash 等命令的代码。按键和 dial 在 hardware mode 下不得读取 feature report：这会让固件卡死，直到重新装回模块，见[设备协议](设备协议.md)。
- 不提交 Cooler Master 的软件、固件、SDK 文件、图片或字体。

## 插件

插件位于此仓库之外，见[插件与本地接口](插件与本地接口.md)。很多人都会用到的插件，以后可以变成内置动作。
