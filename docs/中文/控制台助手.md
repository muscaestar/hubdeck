# 控制台助手

原文：[docs/ASSISTANT.md](../ASSISTANT.md)。基线 `0cbdde3`，2026-10-22。此处“主人”指原作者的产品验收人；行为和实验数据沿用上游记录。

HubDeck 内的助手了解用户工作方式并共同构建 profile：查看拥有和使用的应用，提出整套设备草图供实体试用、比较，完善选中的方案，再讨论下一次尝试。

模型**并非内置于 HubDeck**，而是通过用户电脑的 **Claude Code**，以自己的 Claude Pro / Max 或 Anthropic API key 运行。每次回答计入套餐限制或按 API 用量计费。HubDeck 本身没有账号或费用。

两轮独立设计评审确定：**设备先响应，模型提供审美判断**。HubDeck 自己立即生成草图和引导，模型负责完善与对话。保护规则由代码落实。

## 一段对话的步骤

```
HubDeck window ──assistant_send──▶ HubDeck engine
                                     │ first message: quick sketches of the top apps (no AI),
                                     │ shown at once as idea cards
                                     │ starts once per talk (no window):
                                     │ claude -p --input-format stream-json --output-format stream-json
                                     │        --verbose --include-partial-messages --tools ""
                                     │        --mcp-config mcp.json --strict-mcp-config
                                     │        --allowedTools mcp__hubdeck --system-prompt <rules>
                                     │        --setting-sources local --disable-slash-commands
                                     │        --settings {"autoMemoryEnabled":false}
                                     │        --model <yours or picked> --effort <yours or picked>
                                     │        [--resume <id>]
                                     ▼
                                   Claude Code ──(your account)──▶ Claude
                                     │ calls tools
                                     ▼
                                   hubdeck.exe --mcp-assistant ──HTTP──▶ HubDeck's local API
                                     (drafts only, guard)                makes drafts, idea cards
                                     │
   window ◀──assistant://event── engine: text pieces, the whole text, ideas with their drafts,
                                  answer buttons, remembered notes, tool use, the end of a turn
```

1. **提问与同意**（主人选 2a，2026-10-14）：Get started 有独立助手卡，输入框、Send、三个示例。首条消息后，`assistant_scan` 生成随消息发送的文本：常用应用名和时长、连接/拥有模块、profile 名和偏好笔记。已安装应用/游戏不随 scan 发送，模型需要时用 `list_apps` / `list_games` 查。简短确认展示消息、发送内容一句话、What exactly 精确文本、Send、Send without the app list（`deckText`）、默认勾选 Don't ask again。回答保存在窗口 local storage 供后续使用，之前不发任何内容。
2. **首条消息**：HubDeck 为最常用三个应用立即生成 quick sketches，以 preset 或 starter 为基础适配连接模块，套 house look，保存 draft 并展示。每段 talk 启一个 Claude Code，写入一行 `stream-json`，包含 scan、草图列表、精简 catalog（每动作的 input/params、hotkey 名、LED 效果、快捷键包）及用户消息。
3. 模型一有想法就调用一次 **`propose_idea`**，HubDeck 立刻生成 draft、窗口添加卡片，并把未通过检查的控件及原因返回模型。**`offer_choices`** 提供回答按钮，**`remember`** 保存长期偏好并显示 Remembered 和 Forget。文本边生成边显示。
4. `result` 行表示一轮结束，进程保持供下条消息。Stop 或换模型终止进程，下条消息用 `--resume` 重启。
5. **Try** 在设备显示 draft，不设为 home；**Compare all** 将多份 draft 放在设备上，转 dial 切换；**Pick** 把 draft id 交给模型，原地完善并用 `try_on_deck` 展示；**Use this** 转正式 profile；**Throw away** 删除，保留/丢弃都写入 `taste.json`。
6. **Show me on my deck** 用 `make_tour` / `assistant_tour` 立即生成个人引导：Discover HubDeck 首页面向常用应用、显示真实图标，另页游戏带封面；放上设备，由模型讲解。

原作者测试副本（2026-10-12，Opus 5.5、medium effort）：快速草图 0.7–0.9 s；模型首个想法 12–17 s；完整首轮 30–42 s。之前首卡约 70 s，tour 约 6 min。

## 助手能力范围

- `--tools ""` 关闭 Claude Code 自身工具：无文件、命令、web。
- `--strict-mcp-config` 与 `--allowedTools mcp__hubdeck` 限定只有 HubDeck tools。
- **代码限定 draft**（`mcp.rs` 的 `assistant_call`）：`create_profile` 总创建 draft，忽略 `replace`；对用户自己的 profile 拒绝 update_profile、set_control、clear_control、add_page、delete_page、set_lights、try_on_deck；不提供 activate_profile 和 set_deck_lights。
- **Guard**（`guard.rs`，草图也用）：拒绝 `core.run`、`ha.service`；Alt+F4、Ctrl+W、Ctrl+Q、Shift+Delete 等关闭/退出/删除快捷键，包中标记 destructive 的如 Zoom Alt+Q，以及带 Enter 的文本，只能长按，不能按下或旋转触发；multi-action 和 modes 内部步骤也查。
- **核实快捷键**：`list_shortcuts` 返回应用包；助手生成的 profile 若含包外键位，控件显示 Shortcut not checked for this app，卡片显示 N shortcuts not checked。
- `--system-prompt`、`--setting-sources local`、`--disable-slash-commands`、`autoMemoryEnabled: false` 使用户自己的 Claude Code hooks、CLAUDE.md、skills、permissions、auto-memory 不进入该助手。登录仍用用户账号，默认 model/effort 从 `~/.claude/settings.json` 读取并传入。
- 应用名、游戏名、web 值按数据处理，不当成指令，规则文件明确说明。

## 开始对话

首条回复指出 scan 中两三件只有 HubDeck 能为此人做的事，使用真实应用名，然后做短访谈：3–4 问，一次一问，只问 scan 无法知道的用途、烦恼、一键想做什么、风格；回答按钮可多选，提供 All、Send。每答一问给一种具体可能性。之后根据回答提供三个草图，至少一个发挥 live state、dial、灯光或动画等 HubDeck 能力。Skip the questions: surprise me 直接进入建议。草图逐个展示，可箭头、圆点、dial 切换，窗口和设备同步。

## 更大权限（默认关闭开关）

开启 Let it reach further 时，Claude Code 额外获得 Read、Glob、Grep、Bash、WebFetch、WebSearch，并设置 `--permission-prompt-tool mcp__hubdeck__permission_prompt`。命令与 web fetch 在对话中显示 Allow / Allow in this talk / No 卡，等待最多十分钟；Claude Code 自身允许的 echo 等只读命令会直接通过。此时也可把 `core.run` 放上按键。

关闭时，`test_address` 仍可 GET 本机应用 API，仅限 127.0.0.1 / localhost。按键可用 `core.http` 的 method/address/body/headers 调用应用 API，最长 5 s，按键显示状态码。

## 用户自己的应用（phase 12）

遵循[应用接入约定](应用接入约定.md)的应用连接一次（Settings > Connections > Your apps，或本机地址 `connect_app`），`states.rs` 持续监听。助手用 `list_app_states` 读取，构建按状态颜色/图标显示的 `core.state` 按键；dial 的 `app.*` 统计等待项，`core.http` 按键调用动作。

其他工具：`hubdeck_state` 了解实际设置，避免承诺未开启能力；`tried` 读取 draft 试用期间触碰控件；`key_usage` 统计各控件频次，仅用户在 Get started 或引导末尾开启后可用。

## 对话外建议

无需 AI：某应用前台累计 30+ min、出现 2+ 天且无 profile，或首次连接某类模块时，Get started 出现圆点和安静的卡片。Show me a sketch 生成并试用自有草图；Ask the assistant 预填首框；Not now 安静 7 天；Don't suggest this 安静 30 天。每天最多一次，通话、游戏前台、试用 draft 期间不提示。在 What it remembers about you 可关闭；无弹窗，不接管设备。

## 发送与保存

- 经 Claude Code 发给 Claude：经用户允许的 scan（未排除的常用应用、设备、偏好）、catalog、消息与 tools 返回的动作、图标、draft、快捷键包。不发屏幕、文件、window title。
- Claude Code 像其他 session 一样把对话存为 `~/.claude/projects/C--Users-<user>-AppData-Local-Temp-hubdeck-assistant/<session>.jsonl`。终端读取或继续：`cd %TEMP%\hubdeck-assistant` 后 `claude --resume <session id>`，窗口显示 id。
- `usage.json`、`taste.json`、`nudges.json` 留在 HubDeck 数据目录。

## 没有 Claude Code

tab 说明需要 Claude Code 和 Claude plan / API key，链接 claude.com/claude-code，并指向无需 AI 的 `+ > For an app or game…` 和现成 profile。建议卡的 Show me a sketch 无需 AI；quick sketches 和 tour 也由 HubDeck 自己生成，但原文当时只在对话里提供。
