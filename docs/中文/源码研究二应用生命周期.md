# 源码研究二：应用生命周期与系统边界

最后更新：2026-10-22。源码基线 `0cbdde3`，静态阅读，没有启动应用。

## 启动顺序

[`main.rs`](../../app/src-tauri/src/main.rs) 先按第一个参数分流：`--claude-hook`、`--mcp`、`--mcp-deck`、`--mcp-assistant`、`--guard`、`cli` 都有独立入口。常规启动才进 `hubdeck_lib::run()`。MCP/CLI 模式无需创建 UI/硬件 hub，因此自有工具应调用这些入口，而非自己启动完整应用副本。

[`lib.rs`](../../app/src-tauri/src/lib.rs) 的 `run` 顺序为：

1. 读取 automation 模式，必要时在创建线程前设置 WebView2 环境。
2. 普通模式装 single-instance plugin，第二次启动转交文件并显示已有窗口；注册 log、opener、dialog、autostart、updater、process。
3. setup 中保存 AppHandle，安装 panic hook，取得设备锁，决定数据目录，迁移旧数据，启动外部 guard。
4. 载入 Placements，启动 Engine，给 Deck 注入 engine sender，读取朝向设置。
5. 安装版首次自动启用 autostart，并设 autostart_offered，之后不会反复重开用户关掉的自启动。
6. manage Engine，安装本地 API 路由，恢复 tour 状态，处理自动 profile。
7. automation 走虚拟模块分支；film 特例走真实设备；正常分支启动 Deck、系统电源监听、托盘、更新检查、插件文件处理与 Windows 文件关联。

`take_the_deck_lock` 在 temp 的 `hubdeck-deck.lock` 持有进程级文件锁，补足 single-instance 的硬件独占；重启让旧实例最多 10 s 释放。拿不到文件等异常有日志分支，不能仅凭安装了 single-instance plugin 认定绝无并发。

旧标识 `dev.masterhub.app` 迁移到 `dev.hubdeck.app`，只在新数据目录尚不存在时复制设置、placements、profiles 等；不应把它当通用 schema migration。

## 设备桥 `deck.rs`

[源码](../../app/src-tauri/src/deck.rs)。Deck 是可 clone 的共享设备服务，独立线程运行 Hub，向 `deck://event` 发 UI event，并向 Engine 发统一 `InputEvent`。

- UI 模块 id 为 `kind:serial`，控件动作 id 则只用 `keys.N`、`knobs.N` 等。后者不含 serial，反映当前应用主要面向一套同类控件的设计；多底座需要重新设计路由。
- Snapshot 包含模块/firmware/slot、orientation、turn、手动覆盖、unresponsive、paused、推杆初始值、寻找时长。窗口打开晚也能获取实际推杆位置。
- `base_turn`：horizontal→270，vertical→180；手动角度归一为 90° 的整数倍。Snapshot 上方注释仍有 vertical=0，实际函数和测试为 180。
- `set_paused`/`suspend` 停 Hub 并归还固件；resume 后等 USB 2 s。退出 `stop` 等待释放最多 8 s；休眠等待 1.5 s。
- `released-at` 跨进程记录交还时间，再启动补足 6 s settle，规避接管过快。
- `module()` 在 stop 置位后不再向新请求提供 handle，配合 worker 关闭避免交还后的写入。
- `spawn_virtual` 与 `virtual_input` 可用虚拟模块跑 UI/engine；初始推杆 Level 只更新值和 LED，不立即触发用户动作。

## 输出桥 `output.rs`

[源码](../../app/src-tauri/src/output.rs)。三个 Tauri command 为 `draw_jpeg`、`fill_screen`、`set_leds`，先按 UI id 找模块，再用 spawn_blocking 写设备。screen 类型与 ModuleKind 不匹配返回错误；JPEG 只交给报告 builder，本层不验证像素尺寸。

`set_leds(None)` 恢复 rainbow；Some 则先 Static，再逐 index 发颜色，`persist=false`。这条直接输出路径与 engine 持续渲染不同，用它调试时可能在下次 engine redraw 被覆盖。

## 外部进程守护 `guard.rs`

[源码](../../app/src-tauri/src/guard.rs)。这是崩溃恢复进程，和 `engine/guard.rs` 的助手动作约束是两种模块。

主进程启动自身 `--guard <data> <logs>`，保留其 stdin。正常退出发 `bye\n`；崩溃/强杀关闭 pipe，guard 通过 EOF 得知，无轮询 CPU。异常时截取最多 60 行日志，打开 Hub 等模块连接稳定 1.5 s（最多 8 s），close 交还，写 released-at 和 last-crash.json。

debug build 不自动重启；release 等 3 s，Windows 关机不重启；10 min 内最多 3 次，计数持久保存到 guard-restarts。`crash_report` 返回前经 diagnostics scrub，`crash_seen` 移为 last-crash.seen.json。更新前也先 leaving，避免旧版本被 guard 误拉起；安装失败路径会重新建 guard。

## 托盘 `tray.rs`

[源码](../../app/src-tauri/src/tray.rs)。`show_main` 按需创建 WebviewWindow，显示/聚焦；关闭窗口释放 webview，engine 与 tray 继续运行。`refresh` 根据 profile/active/pinned/paused/autostart/update 的签名判断是否重建菜单，避免无变化重复操作。

菜单覆盖 profile、pin、pause、自启动、日志、诊断、退出，游戏入口受 `GAMES_ENABLED` 控制。诊断用 module snapshot、经裁剪 settings、plugin 列表和清洗日志，保存后 reveal；automation 会拦打开外部窗口。只有 Quit 的显式退出码触发进程退出，关最后窗口 `ExitRequested code=None` 被阻止。

## OS 适配 `system.rs`

[源码](../../app/src-tauri/src/system.rs)。Windows power callback 用进程常驻 Deck 指针连接 suspend/resume。恢复模块按 vendor/PID 枚举所有对应设备，UAC runas PowerShell 调 pnputil；不是按当前不可信 serial 寻找，且操作的是该类型所有已连接模块。取消 UAC、未找到、退出码分别报错。

shell_open 在 Windows 用 ShellExecuteEx，支持应用名/App Paths/协议；macOS app 名用 `open -a`，普通文件/URL 走 opener。automation 先截断外部打开。非 Windows 电源通知仍 TODO，不可把 USB 断线恢复当成完整 sleep lifecycle。

## 持久位置 `placements.rs`

[源码](../../app/src-tauri/src/placements.rs)。`kind@slot` 映射 col/row/rotation，JSON version 1，内存 Mutex，临时文件+rename，损坏/缺失回退空。现有测试覆盖往返、删除、坏文件。

**实现差异待核对**：Rust Placement col/row 为 `u8`，上游 0.1.5 文档与生成表允许 row=-2 等越界位置。生成表/前端允许负坐标，并不自动证明手动 placement API 也能保存负值；这条类型边界要在后续功能开发时专测。

## 更新 `update.rs`

[源码](../../app/src-tauri/src/update.rs)。读取配置 updater pubkey，空值表示当前 build 未配置。查新只取信息；明确请求后下载、校验并安装，再重启。release 普通启动可按设置每 6 h 重查，不自动安装；AVAILABLE 缓存让之后才打开的窗口/托盘也知道更新。

当前 `tauri.conf.json` 已填上游公钥，空值禁用是条件逻辑，不是此快照的实际配置。

回退从最多 30 条 upstream GitHub release 找比当前小的最新稳定版，排 draft/prerelease/带 `-` 版本；先备份再安装签名更新。相关测试覆盖 release 版本挑选。**fork 注意**：release API 和 updater 仍指向 `Przemotar/hubdeck`，文档改成中文不会自动变更更新来源；自行发布前需配置自己 release/signing，而非随意沿用上游签名。

## 文件关联 `assoc.rs`

[源码](../../app/src-tauri/src/assoc.rs)。仅 Windows 安装版注册当前用户的 `.streamDeckPlugin` Open with。已有默认关联则不抢；无默认才设 HubDeck。路径随每次启动更新；卸载 hooks 清理该注册。debug 不注册，译文不会执行此代码。

## 自动化 `automation.rs`

[源码](../../app/src-tauri/src/automation.rs)。`HUBDECK_AUTOMATION` 指定独立 data/log/webview，`HUBDECK_CDP_PORT` 默认 9333，虚拟模块默认 base/keys/dial/knobs/rollers。无托盘、单实例、自启动、update，窗口无焦点移到 -20000。`HUBDECK_FILM_DECK` 是例外：自动化仍用真实硬件，不能混同纯虚拟测试。`blocks_opening` 截断链接/文件打开，但不能推断所有系统动作都被统一 sandbox。

现有 tests 验证虚拟模块 spec 解析和坏条目忽略。Playwright 工具由本地 CDP 驱动窗口，后续见工程研究。

## 退出路径与二次开发

常规 Exit：Deck.stop → mark_released → plugins.stop → usage/presses.flush → macOS 音量释放 → guard.leaving → stopped log。新增设备 worker 必须接入该生命周期，不能只在窗口卸载时停止。

新增功能通常应进入 engine/action 或独立插件。新增 Tauri command 同时更新 lib.rs invoke_handler、前端 wrapper、输入检查；耗时 I/O 走专用线程或 spawn_blocking。崩溃、升级、暂停、休眠、窗口关闭是不同状态，文档和测试应分别覆盖。
