# 源码研究六：助手、预设与交互

最后更新：2026-10-22。基线 `0cbdde3`，静态研究。这里的“助手”是 HubDeck 产品内的 Claude Code 集成，与本次整理文档的工具无关。

## `assistant.rs`：会话与草稿

`assistant_scan` 汇总已连接/曾拥有模块、现有正式配置、前台使用统计、已识别安装应用和 taste；窗口可以选择不发送使用信息，改用 `deck_text`。应用列表最多取 25 项、过滤很短的使用记录，已知安装应用最多 60 项。这不是全盘文件扫描。

`Talk` 保存进程、stdin、session、busy 和 run 序号。`assistant_send` 防止并发发送，第一条消息加入用户预览过的 scan 和 catalog，后续通过 stream-json stdin 继续对话。`start` 启动隐藏的 Claude CLI，使用自己的 system prompt、严格 MCP 配置和临时目录，默认一般工具为空；可恢复 session。stdout 被解析成 `assistant://event`，stderr 在失败时展示尾部。run 序号防止旧进程退出误清新会话状态。

文件头“每轮一次 claude -p”以及 `assistant_send` 上方“首次立刻做 sketches”的注释已经落后于代码：当前保留 stdin 会话；实际 first-message 分支明确改为采访后再做草稿。研究实现时应跟踪执行分支。

`sketch_profile` 把 Idea 转成具体 Profile，`with_real_apps` 尝试关联实际应用，`save_sketch` 写草稿，`api_idea/choices/tour/remember` 通知窗口或更新本地记忆。比较草稿和决定采用仍交给 Engine 的 draft 生命周期，不应另写一套正式配置覆盖逻辑。

More power 打开后启用 `Read,Glob,Grep,Bash,WebFetch,WebSearch`，并指定自己的 permission MCP。窗口可选 once/talk/deny；talk 是按工具类别记忆，不是按单条命令记忆。`api_permission` 发卡片，`close_asks` 在停止/重置时拒绝未回答请求并按需要清空许可。注意 `assistant_permit` 对任何不等于 `deny` 的字符串都设置 allow，前端通常只传预定选项；若扩展调用入口，应验证枚举值。

`assistant-rules.txt` 是运行时 prompt，插入语言、house style 等文字；中文翻译仅供读者参考，没有替换它。模型输出约定包含 ideas/choices 等结构，`split_ideas/split_choices/read_line` 对应解析；改 prompt 的同时要检查解析和窗口事件。

## `guard.rs` 与 `shortcuts.rs`

这是 `engine/guard.rs`，与根目录崩溃恢复 guard 不同。它在代码层检查助手生成的 binding：默认拒绝 `core.run` 与任意 `ha.service`；More power 可以放开前者；危险 launch target 默认拒绝；关闭/清除类动作和快捷键只能放 hold，带换行的 text 也需 hold。

`steps`、`modes` 递归检查深度上限为 4；这应当被理解为实现边界，不能声称对任意深度 JSON 都证明安全。编辑器允许主人手工配置更广动作，因此这不是全应用权限系统。

`shortcuts.json` 存放按应用/OS 区分、有来源 URL 的 shortcut packs；`shortcuts.rs` 负责 normalize、wildcard 匹配、checked/destructive 判断。媒体键可以通用，Alt+F4、Ctrl+W 等总是按危险组合处理。来源链接代表该快照录入依据，并不保证用户重绑后的实际快捷键；新增赛车游戏应同时写清游戏版本和绑定前提。

## 本地记忆和统计

| 模块 | 数据、行为与边界 |
|---|---|
| `taste.rs` | `taste.json`，最多 30 条可编辑偏好、40 条保留/丢弃历史；`text` 生成下一轮 scan 的摘要。可以清除。 |
| `usage.rs` | `usage.json`，按前台 exe 累计秒数和天数，忽略 HubDeck/锁屏；每段最多算 15 分钟、约 120 秒落盘，退出 flush。属于近似使用统计，不是精确工作计时。 |
| `presses.rs` | 草稿试用 touched 保存在内存；只有 counting 开启才累计正式计数，约 60 秒写 `presses.json`。删除 profile/清除统计有对应入口。turn/slide 记录的次数应结合 Engine 调用点理解，不能直接等同人按了多少次键。 |
| `nudge.rs` | 无模型的主动建议；一天最多一个，通话/游戏忙碌时抑制；新模块、tour 后未用控件、没有配置的常用应用。常用门槛为至少 30 分钟及 2 天；已看过模块有持久记忆，避免重连反复提示。 |

这些文件在本地保存，不自动等于送给模型。开始对话时用户选择的 scan 才决定发送哪些摘要。新增收集字段应同时改扫描预览和隐私说明。

## 从零配置的几条路径

`auto.rs` 在启动时给已识别应用准备待启用配置，首次前台游戏另有立即可切入路径。`settings.offered` 避免删掉后不断重建，`auto_made` 是待查看列表，`auto_profiles` 控制开关。游戏可由 exe 或安装目录辨认；不能把任意未知 exe 都认作游戏。

`starter.rs` 优先选应用专用 preset，其次 shortcut pack，再按 Browser/Editor/Chat/Media/Game/Other 分类生成；加入应用匹配、图片，最后适配用户模块。Windows 还读游戏注册信息。`suggest.rs` 为一个控件按“专用 preset → starter → 通用动作”排序，按 action+params 去重、排除已存在工作，最多 8 项；fill-empty 只填当前 page 的空位。

`builder.rs` 则提供逐控件选择卡片和工作 draft，built-in 优先，再接已安装插件；卡片包含真实 Binding、gestures 和 dial SVG，不是只用来展示的假配置。`gallery.rs` 管理 dial 的 Face、外观、手势和预览，`core.dialGallery` 让设备轮览这些设置。

## `presets.rs` 与样例

主 catalog 包含日常、状态、Claude、会议、创作、游戏和模拟器等配置。编辑类应用用共用 Editor 结构生成，游戏样例通过 `game_preset` 复用布局。`PresetInfo::make` 连接 catalog 与生成函数，最终应用 house style 和语言处理。

`adapt_noted` 是重要的硬件适配器：缺 dial 时可以迁移到 knob；缺 fader/roller 时合并到 knobs 或 dial 的 modes；没有转动控件而有 keys 时，把音量变成 +/- 键，必要时建立 Controls page。它返回 `Moved` 供窗口解释。并非所有缺失动作都能无损搬迁：当前首先收集具有 Turn 输入能力的 binding，其他缺失功能不在这条补偿链里。原 control 内容也可能保留供将来接回模块。

`house.rs` 对产品生成内容应用 graphite 背景 `#1b1a20`、标签 `#e6e4ee`、动作分组的柔和图标色；不应以它强制重写主人自定义外观。

`test_presets.rs` 是人工硬件验收配置：gestures、looks、turning、integrations、panel、真实应用、aurora 等；它不是单元测试 runner。`showcase.rs` 的 Stream Live/Night Focus/Spotify Studio 展示统一风格，导入时把内置图片放到图片库。相关生成脚本见原型研究。

## 两种 tour

`demo.rs` 的 Discover 是带说明的七页配置，用 `look.note = demo:<id>` 让窗口解释按键；底部导航循环，dial 使用 gallery。它与 `tour.rs` 的个人化逐步引导不同。

`tour.rs` 根据模块、OS、应用和用途生成 home draft，保存音频快照后试用，每站可 keep/leave/look。`tour_dry_run` 只拦截已列出的直播/录制/部分命令等动作，不是任意动作都自动回滚。`tour_finish` 可保留并设 home，Exit 丢 draft 并恢复音量/麦克风，`recover` 在下次启动处理未结束的 snapshot。音频恢复依赖实际设备仍存在、调用成功；此处没有做本机声卡实验。

资源 `resources/tour/loop.wav` 用于演示，`tour_sound`、saver preview、highlight 都有独立收尾。增加新 tour 动作时应检查 dry-run 清单、取消路径和崩溃恢复。

## `games.rs` 与 `pet.rs`

这里的 games 是控制台内置小游戏，和“游戏启动器/赛车游戏 preset”分开。`Game` trait 只接输入与时间，返回 Screen；Mole、Simon、Safe、Snake、Arena、Rhythm、Pong、Duel、Wheel、Memory、Reflex 共 11 个状态机共享 Arcade 的 launcher/playing/over、分数和离开逻辑。长按 dial 1 秒逐级返回。**当前 `GAMES_ENABLED = false`**，因此存在实现不代表发行界面已开放；后续可作为纯逻辑测试参考。

`pet.rs` 是 dial Mochi：Needs 持久化到 `pet.json`，Fullness 约 8 小时从满到空，Joy 常量为 12 小时；旧注释“约 5 小时”已过时。睡眠暂停衰减，任意轻触可先唤醒；转动增加 joy、按压抚摸、双击喂食、hold 切换睡眠。mood 优先考虑睡眠/锁屏，再饥饿、伤心、夜间困倦。

渲染用程序 SVG，支持 body 图片与保留原绑定；16.8 秒休息循环、40 ms step 共 420 帧，减少重复工作。不是一套完整养成系统，源码明确未来才考虑成长和配饰。`pet_preview` 与 UI 走相同绘图函数。

## 验证与扩展建议

现有测试覆盖快捷键归一化、guard、preset drawable/action、适配结果、nudge 抑制、usage 累计、pet 行为、tour 组装以及游戏状态机。它们不能证明第三方程序当下真的响应快捷键、麦克风已经恢复或屏幕没有花屏。

自己的开发可先沿 starter/presets/shortcuts 添加赛车用途，再通过 API 接遥测；需要动态状态的功能应走 Engine integration/render，避免让助手 prompt 直接承担设备状态机。
