# 开发案例：HubDeck，为失去支持的控制器提供开放应用

原文：[docs/CASE-STUDY.md](../CASE-STUDY.md)。基线 `0cbdde3`，2026-10-22。

作者：Przemysław Tarkowski（przemotar+hubdeck@gmail.com），2026 年 10 月。下面是作者的开发叙述和测量。

## 问题

Cooler Master MasterHUB 是模块化桌面控制器，带边缘灯底座和磁吸模块：15 个 LCD 键、240×240 圆屏 dial、LED 环旋钮、推杆、滚轮。2024 年 Kickstarter 众筹，2025 年发货。硬件优秀，官方软件跟进不足；向支持者承诺的 SDK、macOS、更多集成未交付，用户报告延迟、设置丢失、切换慢，担忧长期支持。

写代码前，作者从评论、厂商论坛、release note、同类产品 GitHub issue 收集 **170 个来源、109 个痛点**，注明频率及修复办法。还把官方应用作为数据阅读，以了解用户依赖的动作和 profile 格式，见[官方应用对比](官方应用对比.md)。

## 方法

**协议优先，实机验证**：模块用 USB HID。以 MIT 社区 probe 为起点，反汇编厂商 SDK library 补缺，用 Python 原型按模块类型逐命令核对。结果记录于[设备协议](设备协议.md)，作为 Rust protocol crate 的依据。

**把保护落实为规则**：固件支持序列号重写、复位、刷固件，HubDeck 不实现这些命令且拒绝手工 report。还发现 hardware mode 读按键/dial feature report 会卡死，需断电。engine 不做此读，检测无响应，并说明 USB restart 或重新装回的恢复办法。

**作者决策，agent 实现**：每个视觉选择由作者从两三份完整方案（窗口、设备图、底座灯）选定；每个功能经自己硬件体验才认定完成。

## 架构

- Rust `mh-protocol`：协议编解码，无 I/O，有单元测试。
- Rust `mh-device`：USB HID、热插拔 hub，每模块独立 reader thread，整图在一把锁下发送。
- Tauri 中的 Rust engine：profile、action、gesture、home 自动切换、LED、SVG/resvg 屏幕与同源预览；OBS、Streamlabs、Spotify、Home Assistant、MIDI、Twitch、Claude Code；本地 WebSocket 插件、API、备份、诊断。
- React 窗口：实时画出桌上设备、动作库和编辑面板，只在打开时创建，托盘运行开销很小。

见[架构](架构.md)。

## 测量结果

| 项目 | 之前 | 之后 | 方法 |
|---|---|---|---|
| profile 切换绘制 15 键 | 3.3 s | 36 ms | engine 分阶段日志；约 100 个 reports 逐个发送，reader 每次间隙占锁读 20 ms。一次锁发整图解决，非 USB 带宽 |
| 托盘空闲 CPU | 单核 28.8% | 单核 0.76% | 接设备的 release build，30 s 进程/线程 CPU；原因是每秒耗 1.1 s CPU 的系统信息调用、每秒 USB rescan、隐藏 webview |
| 空闲内存 | 约 430 MB | 45 MB | 同次 app+webview working set；隐藏窗口占 346 MB，现关闭就销毁 |
| 作者对切换的体感 | 3–4 s | “现在切换瞬间完成” | 桌面安装版 |
| macOS 旋钮系统音量 | 每格约 0.2 s，快转跟不上 | 小于 1 ms | AppleScript 改 Core Audio，逐 call 计时 |
| macOS hover 窗口帧时 | 均值 52 ms，十分之一超过 100 ms | 17 ms | Playwright WebKit 记录 requestAnimationFrame；颜色动画导致设备图 SVG filter 每秒重绘十次 |

还测得每屏每秒接收约 32 张图，整按键面板 USB 传输 11–36 ms。

## 构建过程

以 Anthropic coding agent **Claude Code** 开发，作者任 product owner 和 tester。工作规则写进仓库，使每段 session 都从项目状态、带原话和日期的决策、问题因果与修复日志、已验证协议开始。

第三天起多个 agent 共享一库并行：Rust engine/集成、设计/窗口、协调/文档。作者回答、选方案、实机测每版。共享 working tree 要只 stage 自己的改动并在同一步提交等经验，直接写入知识日志。

进度数字：前两天实机可用；后几天加入 profile、约 70 动作、七项集成、插件、本地 API、深浅新窗口、游戏/创作预设、图标包、分享；首周内完成 macOS port、Stream Deck 插件和助手；200+ Rust tests、前端 tests，每次修改都点通窗口。

## 一天移植到 macOS

首个 Mac session 从仅 Windows 跑过的应用开始，无修改即编译。当天处理并实机核实：IOKit `locationID` slot，沿用 Windows 表；已装应用与 Finder 图标；用 Spotify/Music scripting 取当前播放（系统接口为 private）；Core Audio 音量；清晰的 Accessibility 提示；重启后模块偶尔无响应追至模式切换后读得太早，增加等待规避固件问题。

## 无需逐个编写的数百集成

用户已有喜爱的 Stream Deck 插件。HubDeck 根据 Elgato 公开 SDK 文档实现兼容协议，启动 Node/native/HTML 插件，15 键映射 5×3，dial/knobs 映射 dials，显示原插件 settings，渲染 title/image/dial layout，甚至歌曲封面后面的进度环。原作者验证 Stream Deck Spotify 插件在 MasterHUB 使用，见[插件兼容](StreamDeck插件.md)。

## 共同设计设备的助手

多数用户难以配置：选择多，不知可能性。助手运行自己的 Claude Code，经允许查看常用应用，问几问，给整套草图供实机体验后保留；或逐控件尝试选项。只改 draft，其他操作需要点击，见[控制台助手](控制台助手.md)。
