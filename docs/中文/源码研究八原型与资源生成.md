# 源码研究八：Python 原型与资源生成

最后更新：2026-10-22。基线 `0cbdde3`。原型保存逆向过程和实验，不是当前 Rust 驱动的等价实现。本次只读源码，没有打开 HID、切换 USB 状态或运行资源生成器。

## `prototype/masterhub/`

`__init__.py` 为空，用作 package 标识。`driver.py` 定义 Module、六种设备类、Event、JPEG 编码与 report builder；`hub.py` 提供热插拔 runtime。

驱动用 hidapi 的 Python binding，每模块一个 handle。Output report 长度先尝试从 descriptor 解析，失败使用 fallback；write/send_feature 分别补齐长度、经 `_guard` 拒绝危险 report-command 对；get_feature 按返回长度裁掉 header。图像以 8 字节 header 分块，带 chunk index、length、screen index、last flag。

`_M0` 共享 LED 功能，Base/Faders/Knobs/Rollers 各自解析输入；Keys 处理 5×3 的全量 key 状态及 72×72 key JPEG/480×272 panel；Dial 处理方向/按压和 240×240 图片。`open_all` 按模块名称放字典，同种多个模块会覆盖，不宜直接作为多模块正式 runtime。

Keys 初始化是 software-on、等待 200 ms、读 firmware，最多三次，重试前 off 300 ms；Dial 只开 software mode 再等 200 ms。Rust 已增加更保守的二次开模式、等待与恢复策略。Python 没有自动继承这些修复。`Keys.serial_number` 与 software mode 共用 0x3A 的历史实现也应与协议原件、Rust 逐项比对，不能据函数名就认定适合当前设备。

Python write 的锁按单个 report 获取，`send_chunked` 不持有整张图的传输锁；并发图片可能交错。Rust picture worker 和 device 写入有自己的序列化设计，新增业务应优先基于 Rust 或本地 API。

`Hub` 默认每秒枚举；按 serial（缺失则 path）记录设备，初始化成功后启动 reader，调用 on_connect 重画。reader 把全量 keys、knob press 和 fader 转成变化事件，过滤 heartbeat，错误后移除并让 scanner 重连。`close` 先停 scanner/readers，再 release software mode 和 close handle，避免在 read 中关闭。这里的有限 join 等待与异常吞掉只是实验程序取舍，不是成功归还设备的保证。

## 设备实验逐项说明

以下路径均在 `prototype/tools/`。表中的写入/系统行为来自实际代码，不代表本次已执行。

| 文件 | 用途与作用范围 |
|---|---|
| `probe.py` | 枚举六种 PID 并读 feature 信息；keys/dial 必须先开 software mode，最后归还。它包含写 mode，不能称纯读取。 |
| `listen.py` | 只读各模块 raw input report，打印 tag/length/payload；不做 Engine 的手势和动作。 |
| `usbwatch.py` | 每 100 ms 枚举，不打开 handle，打印设备消失/回来，统计 keys drop 次数；names 表缺 faders 友好名时会显示 hex。 |
| `state_check.py` | 反复枚举、开 software mode、读 firmware、关 mode，检查 USB strings/feature 响应；不是不改变状态的健康查询。 |
| `keys_test.py` | 接管 keys，读取信息、填色、写单键图片并监听，最后归还 hardware mode。 |
| `screen_test.py` | 每次更新整幅 480×272 panel 渐变，观察跨键屏幕传输。 |
| `layout_a_test.py` | keys/dial/knobs/rollers 联动：转动改 dial 值、keys 整屏、knob LEDs。头注释“dial 未解码”已过时，driver 已解析。 |
| `demo.py` | 热插拔 Hub 演示，编号键、按下变色、fader 红绿变化、base cyan，重连后重绘。 |
| `hid_idle.py` | 使用 libusb/pyusb 检查 GET_IDLE，`--set` 才发 SET_IDLE(0)，用于 macOS roller 无输入调查；不写固件存储，但会改运行态。 |
| `recover_test.py` | Windows 故障注入：**主动在 hardware mode 读 feature 卡住 keys**，再尝试重开/切模式及 USB port cycle。不是常规排障首选，不能误当日常自测。 |
| `restart-keys-module.ps1` | Windows 管理员级 PnP restart，交互确认后 disable/enable 设备节点。会影响真实 USB 设备；本次未运行。 |

这批工具有些使用相对 `tools/` 的旧命令，实际位置已经移到 `prototype/tools/`。复现时应以当前文件路径和导入方式为准，记录 Python、hidapi 和 OS 版本。不要在正式 HubDeck 同时占用设备时直接照抄实验命令。

## 资源生成器逐项说明

| 文件 | 输入、输出与算法 |
|---|---|
| `gen_samples.py` | Pillow 生成 ring/dot GIF、gradient PNG 和 panel，写 `resources/samples/`，供人工测试 preset。 |
| `gen_animations.py` | NumPy/Pillow 生成 aurora、fire、loader、bars，控制尺寸与帧间隔；供样例动画。 |
| `gen_demo_art.py` | 使用现有 Lucide paths、HSL 和程序几何生成 neon/glass/panorama 三种风格；无 style 参数输出比较 HTML，有 style 输出 SVG。 |
| `gen_demo_gifs.py` | house 色系的 72 px key/240 px dial 动画：ping、spinner、scope、rain、fire、bars 等；写 `resources/demo/`。 |
| `gen_house_style.py` | 比较统一按键风格，组合图标、假应用图标、标签和 panorama，输出 variants HTML；源中采用嵌套 f-string。 |
| `gen_showcase.py` | 固定 random seed 7，生成直播 scene、跨 15 键夜空和 equalizer，写 `resources/showcase/`；标签由应用后绘。 |
| `gen_slots.py` | 输入官方应用 source map 中的 board CSS，抽取像素位置和旋转，换成网格坐标；旋转校准与模块 offset 生成已知条目，再根据 connector 几何推导缺项，输出 `app/src/slots.generated.json`。仅导出派生数字。 |

`gen_slots` 用 129 px pitch、25 px origin 和 180° board 转换；derive 枚举半格 connector 候选，按已有条目一致性选模型。推导坐标与真实接点确认是两种证据；verified 标记和主人分享的布局应保留，不能把推导项全部升级成实测。

资源生成脚本会覆盖产物；没有必要为了翻译重跑。当前 Python 3.11 在静态 AST 解析 `gen_house_style.py` 时对嵌套 f-string 报 SyntaxError；可能依赖更新语法环境，需要另行确认脚本的 Python 版本要求，本次没有修改原型来迁就本机解释器。

## 与后续开发的关系

Python 很适合保留小范围可解释实验，但应该单独标注故障注入、读操作和运行态写入。新增逆向发现先记输入输出的原始 report、设备/固件/OS 和可复现步骤，再移植到 `mh-protocol` 的纯构造/解析测试，最后接 `mh-device` 实物验证。资源生成与设备通信无关，可以独立重现和审查。
