# MasterHUB 音频设备插件

最后更新：2026-10-26。状态：已在本机部署并通过下述技术检查，待主人验收。

## 本版范围与交互

只控制两个输出预设：BRAVIA 普通播放端点，以及 INZONE-Game。每个设备占一个按键，按下后将该端点设为 Windows 默认输出。麦克风和圆屏常驻显示不在本版范围。

| 稳态 | 显示 | 按键行为 |
|---|---|---|
| 未连接 | 灰色，设备名＋“未连接” | 提示设备不可用，不切换其他端点 |
| 系统默认输出 | 绿色、勾号，设备名＋“系统默认输出” | 提示已经是默认，不重复改设置 |
| 已连接但不是默认 | 蓝色，设备名＋“已连接” | 切换到该设备，读取系统结果后更新高亮 |

启动时短暂显示“读取中”；读取超时或系统返回错误时显示“读取失败”，不会把错误误报成未连接。切换过程显示“切换中”，失联会超时恢复。颜色之外也有文字区分。

这里的“已连接”是 Windows 将音频 endpoint 标记为 active，可以被选为播放端点；并不独立检测蓝牙电量或无线耳机是否戴上。若耳机的 USB 接收器仍提供 active endpoint，耳机关机时系统也可能仍将该端点视为可用。

## 主程序与插件的分工

- [audiodev.rs](../../app/src-tauri/src/engine/audiodev.rs) 复用已有 Windows 音频实现，新增按 endpoint ID 精确选择。枚举只包含 active endpoint，预设 ID 不在列表即显示未连接。
- [engine/mod.rs](../../app/src-tauri/src/engine/mod.rs) 在已有 COM 初始化的 worker 中处理两个新增消息，将结果发回请求插件。
- [manifest.json](../../plugins/audio-devices/manifest.json) 声明一个 `dev.hubdeck.audio-devices/select` 动作，包含预设、可选 ID 覆盖、显示名称。
- [plugin.mjs](../../plugins/audio-devices/plugin.mjs) 读取配置、连接本地 WebSocket、注册，连接断开退出，由 HubDeck 负责重新启动。
- [controller.mjs](../../plugins/audio-devices/controller.mjs) 保存当前可见 binding、每秒查询实际状态、按键切换、超时与失败处理。离开所有插件 binding 后停止轮询。
- [visuals.mjs](../../plugins/audio-devices/visuals.mjs) 生成带中文状态的 SVG，图像通过宿主渲染后送到设备。只有显示内容变化才发送新图。
- [controller.test.mjs](../../plugins/audio-devices/controller.test.mjs) 使用虚拟时间和消息验证状态联动、失败和超时，不连接硬件、不切换系统音频。
- [devices.example.json](../../plugins/audio-devices/devices.example.json) 提供两台设备的配置结构；真实 endpoint ID 保存在本机 `devices.json`。

不使用外部音频切换工具，不另开 HID，不引入 npm 包；运行需要 Node.js 22+。这是此 fork 的原生插件，未修改的上游 HubDeck 不认识新增音频消息。

## 新增 WebSocket 消息

现有注册认证方式保持不变，参见[插件与本地接口](插件与本地接口.md)。`requestId` 由客户端提供，宿主原样返回。

```json
{"event":"getAudioDevices","requestId":"read-1"}
```

成功响应：`event: "audioDevices"`，带 `outputs`、`inputs` 两个数组；设备字段为 `id`、`name`、`default`。`default` 读取 Windows `eConsole` 默认角色。失败响应带 `error`，不会伪造空列表。

```json
{"event":"setAudioDevice","requestId":"switch-2","kind":"output","deviceId":"<exact endpoint id>"}
```

`kind` 仅接受 `output` 或 `input`。宿主先在对应方向的 active 列表查找精确 ID；缺失、错误方向、空 ID 都返回失败，不做名称猜测。响应为 `event: "audioDeviceResult"`，带 `ok`、`name` 或 `error`。

切换沿用现有 `audiodev` 行为：设置 `eConsole`、`eMultimedia`、`eCommunications` 三种默认角色。因此按下蓝色设备键也会修改默认通信输出；不会修改某个软件内部固定选择的设备，也不能保证所有软件立即迁移已有音频流。若某个角色设置失败，已有调用不提供事务回滚，插件会读回系统实际默认状态。

## 安装与配置

1. 使用包含上述宿主接口的本地 build，构建方式参见 [Windows 本地构建](Windows本地构建.md)。
2. 将 `plugins/audio-devices` 中的运行文件复制到应用数据目录的 `plugins/audio-devices`，不需要复制测试文件。

```powershell
$pluginRoot = Join-Path $env:APPDATA 'dev.hubdeck.app\plugins\audio-devices'
New-Item -ItemType Directory -Path $pluginRoot -Force
'manifest.json','plugin.mjs','controller.mjs','visuals.mjs','devices.example.json' | ForEach-Object {
    Copy-Item -LiteralPath (Join-Path 'plugins\audio-devices' $_) -Destination $pluginRoot
}
```

3. 将 `devices.example.json` 复制成同目录 `devices.json`，填入本机 endpoint ID。该文件属于个人配置，由源码插件目录下的 `.gitignore` 排除。没有 `devices.json` 时，只按示例里的完整名称做唯一精确匹配；重名则要求填写 ID，不会匹配到类似名称。
4. 重启 HubDeck。在插件列表确认“音频设备”已连接；新建“音频设备” Profile，在两个键上分别绑定该插件的 BRAVIA、INZONE-Game 预设，将图片布局设为 `fill`。
5. 本次按主人选择新建独立 Profile，不改写 My deck 原有绑定。以后可以在其他 Profile 复用同一插件动作。

设备更换 USB 口、重配对、重装驱动后 ID 可能改变，需要重新绑定。BRAVIA 的 Hands-Free 与普通播放、INZONE 的 Chat 与 Game 都是不同 endpoint，应分别核对。

## 验证与验收

```powershell
node --test plugins/audio-devices/controller.test.mjs
cargo test --locked --release -p hubdeck --lib plugin_tests
python scripts/check-docs.py
```

Rust 的 `plugin_tests` 只验证 endpoint 精确选择，不调用设置系统默认设备的函数。旧的 ignored `list_audio_devices` 测试会重新设置当前默认的所有角色，不属于本插件的只读验证。

主人验收：分别按两个设备键，检查实际声音去向、绿/蓝状态互换；从 Windows 手动改默认设备，检查约 1 秒内更新；断开设备，确认变灰且按下不切到 Chat 或 Hands-Free。系统有时延迟报告无线设备断开，应按 Windows endpoint 的状态判断。技术验证记录会追加在此处。
