# 源码研究九：工程脚本与发布

最后更新：2026-10-22。基线 `0cbdde3`。静态阅读；没有安装/更新 HubDeck、修改系统配置、运行付费模型或发布 release。

## 工程入口和构建配置

根 `Cargo.toml` 的 workspace 有 mh-protocol、mh-device、hubdeck，edition 2024、最低 Rust 1.90。dev 依赖 opt-level 3 降低渲染开销；release 使用单 codegen unit、LTO、opt-level 3、panic abort、strip。`Cargo.lock` 固定解析版本，不能只看依赖范围判断最终版本。

`app/package.json` 使用 React 19、Tauri 2、TypeScript、Vite、Vitest，脚本为 dev/build/preview/test/tauri；`pnpm-lock.yaml` 固定前端依赖。`tsconfig.json` 开严格类型和 unused 检查，`tsconfig.node.json` 用于 Vite 配置。`vite.config.ts` 固定端口 **1460**、strictPort，远程开发 host 的 HMR 用 1461，忽略 Rust 目录；部分旧注释中的 1420 是模板遗留。

`app/src-tauri/Cargo.toml` 把平台依赖分开：Windows bindings、lazy vJoy DLL，macOS Objective-C/AppKit；JPEG SIMD 编码、resvg/tiny-skia、音频和 HTTP 等是正式产品依赖。build.rs 仅 macOS 编译 `hw.m/appvolume.m` 并链接框架/clang runtime，之后调用 tauri-build。mh-device 的 build.rs 另编译 USB re-enumeration helper。

`rustfmt.toml` 统一 Rust 排版；`.gitignore`、`.gitattributes` 管构建/本机产物和换行；`.vscode/extensions.json` 只是建议编辑器扩展。`app/index.html` 是 WebView 的 root/title，前端入口由 main.tsx 接管。

`tauri.conf.json` 的窗口默认不自动创建，1280×820、最小 960×640，原生拖放关闭以兼容窗口内 action 拖拽。CSP 当前为 null；`capabilities/default.json` 为 main window 开 core/opener/dialog。权限配置与插件隐藏 webview 是后续扩展必须核对的边界，不能只加前端按钮。

当前 updater **已有上游公钥**，endpoint 为 `Przemotar/hubdeck`。`tauri.release.conf.json` 打开 updater artifacts、指定 HubDeck Release macOS 签名身份；默认本地构建是 ad-hoc `-`。本 fork 自行发行必须决定自己的标识符、更新来源和签名，不应直接把私钥塞入配置或文档。

`windows/hooks.nsh` 在真正卸载时清理自己的 `.streamDeckPlugin` 关联，update mode 保留；只删除默认值等于 HubDeck 的关联，不抢走其他程序。`dmg/background.html` 是 Finder 安装背景设计源，显示拖入 Applications 和首次 Open Anyway 指引；`background.png` 是生成产物。

## GitHub workflows 和维护模板

| 文件 | 行为 |
|---|---|
| `.github/workflows/ci.yml` | main push/PR，Windows/macOS matrix，Rust fmt/clippy/tests、TypeScript、Vitest，Node 24/pnpm 10，缓存依赖。 |
| `.github/workflows/release.yml` | `v*` tag，Windows 和 universal macOS 安装包，读取 CHANGELOG 对应章节，用 secret 做签名，创建 draft release/latest.json，上传稳定文件名与 SHA-256，追加安装指引。tag 不等于自动公开发布。 |
| `.github/workflows/pages.yml` | 指定路径 push、每日 cron 或手工启动，构建插件 catalog、更新 sitemap 日期、发布 site。catalog 失败 continue-on-error，应用有其他目录 fallback。 |
| `.github/ISSUE_TEMPLATE/*.yml` | bug/feature/slots 的结构化反馈及联系入口；中文版见[问题模板](问题模板.md)。字段 ID 是自动填充约定，不应随翻译改名。 |
| `.github/pull_request_template.md` | PR 的问题、改动、验证和硬件信息提示；已有[中文对照](拉取请求模板.md)。 |

三个 workflow 的 job 都限制 `github.repository == 'Przemotar/hubdeck'`。因此推送本 fork **不会自动得到这些检查或部署**。本次不擅自修改发行工作流；后续启用时应同时处理 secrets、Pages、签名和 fork 链接。

## 一般脚本逐项研究

| 文件（`scripts/`） | 入口、结果与操作范围 |
|---|---|
| `check.sh` | `set -euo pipefail`，依次 fmt、clippy、tsc、pnpm test、三个 Rust package test；失败不再被 tail 管道遮掉。需要已有依赖。此次文档检查使用单独 checker，不宣称此全套运行过。 |
| `automation.ps1` | 创建测试数据副本，默认 debug exe、CDP 9444、共享 Vite；虚拟模块、窗口移出屏幕。Fresh 会删除副本的非 logs 内容；Stop 会强制结束副本。路径参数不能盲目指向主人正式数据。 |
| `test-build.ps1` | 单独 `target/test-build`，thin LTO、16 codegen units、incremental，生成较快的 NSIS 测试包；不是发行性能基准。 |
| `win-install.ps1` | 取 release/test-build 中最新 installer，向真实 app API 请求 quit，等待退出，静默安装，WMI 启动托盘进程。会覆盖安装，不是纯构建检查。 |
| `mac-install.sh` | build app、本机签名身份可用时重签，退出旧进程，替换 `/Applications/HubDeck.app` 并后台启动；真实安装操作。 |
| `dev-restart.sh` | macOS/Linux 数据路径，先本地 API quit 等归还设备，再启动 dev/tray；读不到 API 时行为需结合当前环境，不应惯性 kill 正式进程。 |
| `soak.ps1` | 采样真实 HubDeck 的内存/CPU，默认 30 min/10 s，输出 CSV，CPU 按单核百分比解释。数值目标是作者机器的门槛。 |
| `release-gate.mjs` | audit、安装体积、动画 soak、反复退出重启/模块回归、Windows 窗口性能；默认 5 min、3 次重启、窗口 150 s。真实设备与已安装应用会被操作，即便使用 try 最后恢复也不是无副作用。 |
| `readme-check.mjs` | 检查公开 README 相对链接/锚点、web 请求、GitHub render、过时界面词和截图日期；默认读 `../hubdeck`，假定上游私有→公开导出布局。它的 slug 仅 ASCII，不适合直接校验中文。 |
| `plugins/catalog.mjs` | 汇集 Elgato/OpenAction/GitHub topics，查 repo/release/manifest，过滤无安装文件/已知不兼容，补 star/system/dial/category/tried，输出 site/plugins.json。会联网，数据不是产品静态事实。 |
| `github-new.py` | 用 gh GraphQL 查询上游最近 issues/PR/discussions/comments/replies，按 since 和作者过滤；只读，窗口数量有限且没有完整分页，不能声称找到了全部历史。 |
| `example-app.py` | ThreadingHTTPServer 默认 localhost:4317，三 agent 状态、manifest/status/SSE、focus POST，启动后 announce；列表队列适合样例，不是高并发生产服务。 |
| `personas/personas.json` | 助手用户场景数据（应用、统计、模块、首问）；只作为评估输入。 |
| `check-docs.py` | 本次新增的离线文档检查：翻译映射、本地链接/锚点、代码示例与逐文件覆盖，见脚本自身说明和[核对记录](研究核对与后续开发.md)。不连接设备或网络。 |

release gate 中的阈值：增长 3 MB/min、峰值 400 MB、平均 CPU 15% 单核、installer 60 MB、installed 200 MB；这些是源码快照里的 gate 设置，不能替代本机实测，不能仅凭文档认定达标。

## 示例插件与网站

`plugins/example-counter/manifest.json` 声明一个接受 press/turn 的 count action，start 参数 0–9999，command 为 `node plugin.js`。`plugin.js` 需要 Node 22+ 内置 WebSocket，读宿主环境变量、注册 token；按 context 存 Map，willAppear 初始化、keyDown +1、dialRotate 加 ticks、setTitle/showFeedback 输出。关闭即退出；计数没有持久化，宿主重启会重置。

`site/index.html` 是静态推广页，含 feature/tour/story/FAQ、下载链接、视频和 SoftwareApplication/FAQPage JSON-LD；没有动态应用后端。`sitemap.xml` 提供上游 canonical URL/日期；images/media 为二进制资产，不做文字替换。页面的“不会损坏/brick”属于宣传措辞，不应被理解为对 USB/固件缺陷的绝对保证。协议层仅能明确说明拒绝哪些命令。

网站、catalog 地址、GitHub 支持入口、release URLs 多处仍指向上游。若未来 fork 需要独立品牌/发行，应统一审查，不要只改 README 的下载按钮。
